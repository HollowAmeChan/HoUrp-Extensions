## 2. 旧 HoAOV

目录：

```text
D:\Unity_Fork\lilToon-URP-Extensions\Runtime\AOV
```

核心 C#：

- `HoAovRendererFeature.cs`：旧 HoAOV RenderFeature、RenderGraph path、compatibility path、clear/debug/output pass。
- `HoAovSettings.cs`：HoAOV channel mask、debug mode、render scale、pass event、fallback/debug shader 设置。
- `HoAovShaderConstants.cs`：旧全局纹理名、shader pass 名、材质属性名。
- `HoAovSubject.cs`：通过 `MaterialPropertyBlock` 写对象/材质语义。
- `HoAovGroup.cs`：按角色/部件打包 renderer user value，优先 `SetShaderUserValue`，失败回退 `MaterialPropertyBlock`。

核心 shader：

- `Shaders\HoAOV\HoAovSampling.hlsl`：HoAOV 采样函数，HoPost/HoSSS/Shoost 会读这里的语义。
- `Shaders\HoAOV\HoAovFallback.shader`：材质没有原生 HoAOV pass 时的 fallback。
- `Shaders\HoAOV\HoAovClear.shader`：清理 AOV RT。
- `Shaders\HoAOV\HoAovDebug.shader`：AOV debug view。

关键查询：

```powershell
rg -n "MaskIdTextureName|NormalDepthTextureName|SurfaceDataTextureName|SssTextureName|ShaderPassName|SssShaderPassName" D:\Unity_Fork\lilToon-URP-Extensions\Runtime\AOV
rg -n "PackRendererUserValue|SetShaderUserValue|ObjectCustomMask|characterId|partId" D:\Unity_Fork\lilToon-URP-Extensions\Runtime\AOV
rg -n "HoAovRenderGraphResources|RecordRenderGraph|FallbackShaderTagIds|AovShaderTagIds|SssShaderTagIds" D:\Unity_Fork\lilToon-URP-Extensions\Runtime\AOV\HoAovRendererFeature.cs
```

旧全局输出名：

- `_lilHoAovMaskIdTexture`
- `_lilHoAovNormalDepthTexture`
- `_lilHoAovTangentNormalTexture`
- `_lilHoAovSurfaceDataTexture`
- `_lilHoAovCustom0_3Texture`
- `_lilHoAovObjectCustom0_3Texture`
- `_lilHoAovObjectCustom4_7Texture`

## 8. 旧 Shoost

目录：

```text
D:\Unity_Fork\lilToon-URP-Extensions\Runtime\ShoostPostProcessing
```

核心 C#：

- `ShoostPostProcessRendererFeature.cs`：Shoost RendererFeature 入口。
- `ShoostPostProcessLayer.cs`：layer 设置、AOV composite 字段、effect 参数。
- `ShoostPostProcessEffect.cs`：effect enum。
- `ShoostPostProcessEffectDescriptor.cs`：effect metadata、默认 shader、顺序、是否支持 AOV composite。
- `ShoostPostProcessEffectRegistry.cs`：effect 到 shader 的查询入口。
- `Renderer\ShoostPostProcessPass.cs`：主执行。

- `Renderer\EffectPipeline\ShoostPostProcessPass.EffectDispatch.cs`：effect dispatch。
- `Renderer\EffectPipeline\ShoostPostProcessAovSupport.cs`：AOV 支持逻辑。
- `Renderer\Effects\*.cs`：各 effect 的参数应用和多 pass 逻辑。

核心 shader：

- `Shaders\Shoost\AovComposite.shader`
- `Shaders\Shoost\LayerBlit.shader`
- `Shaders\Shoost\Glow.shader`
- `Shaders\Shoost\IrisBlur.shader`
- `Shaders\Shoost\RGBBlur.shader`
- `Shaders\Shoost\VHS.shader`
- `Shaders\Shoost\CRTEffects.shader`
- 其它 effect shader 在 `Shaders\Shoost\` 下。

关键查询：

```powershell
rg -n "SupportsAovComposite|AovComposite|HoAovRenderGraphResources|ShoostPostProcessAovSupport" D:\Unity_Fork\lilToon-URP-Extensions\Runtime\ShoostPostProcessing
rg -n "CreateCatalog|SinglePass|MultiPass|Stateful|Removed|runtimeOrder" D:\Unity_Fork\lilToon-URP-Extensions\Runtime\ShoostPostProcessing\ShoostPostProcessEffectDescriptor.cs
rg -n "Dispatch|Apply.*Properties|Render.*Pass" D:\Unity_Fork\lilToon-URP-Extensions\Runtime\ShoostPostProcessing\Renderer
```

要点：

- Shoost 是 final image stack，不是 HoPost 替代品。
- 只有部分 effect 支持 AOV composite。
- 旧兼容路径里已经有 `_lilShoostPostProcessTempA` / `TempB` / `TempC` 这类工作纹理；RenderGraph 路径中很多 layer / effect 会按 layer 创建新的 `TextureHandle`。新 RP 可以把这个事实收敛成正式的 ImageDomain `ImageChain` 双缓冲资源策略：普通线性 image pass 走统一 `WorkA` / `WorkB` ping-pong，只有多分辨率、history、original source、AOV composite 或多输出效果显式申请额外资源。

双缓冲 / 资源复用相关查询：

```powershell
rg -n "TempTextureAName|TempTextureBName|TempTextureCName|tempTextureA|tempTextureB|tempTextureC|RecordSinglePassLayer|CreateTexture|TextureHandle source|TextureHandle destination" D:\Unity_Fork\lilToon-URP-Extensions\Runtime\ShoostPostProcessing
rg -n "RecordAovCompositeIfNeeded|OriginalTex|blurA|blurB|Pyramid|History" D:\Unity_Fork\lilToon-URP-Extensions\Runtime\ShoostPostProcessing
```

## 14. 禁止误读

本文不是迁移方案，也不是新 RP 的 ABI 定义。
